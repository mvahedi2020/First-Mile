# Decisions and remaining risks

September 30, 2026 · Recommendations within the authorized First Mile brief.

| Choice | Product reason | Tradeoff / remaining question |
|---|---|---|
| One prepared inquiry and one destination | A first-time administrator can explain one result. | Does this task resemble the person's actual evaluation job? No interviews performed. |
| Destination preview and explicit confirmation | Looking at a suggested setup is different from deliberately using it. | Adds useful friction; human evidence is needed to judge whether wording improves comprehension. |
| Collaborators after first outcome | A single administrator can run this practice alone. | Real value may depend on colleagues; simulation cannot establish that. |
| Separate deferred and simulated states | Skip should not inflate completion or imply a real invitation. | A return visit still requires an understandable account of remaining work. |
| Local persistence with strict version/schema | Return is useful without accounts or customer data. | Browser-specific, removable, and unavailable under some privacy/quota settings. |
| Revision plus full saved-state comparison | Another tab should not silently confirm a stale suggestion. | No transactional cross-tab write lock or distributed collaboration; latest compatible stored state wins. |
| Bounded Undo route | Correct a deliberate local routing attempt within a clear promise. | Clears optional state dependent on that attempt. Reset cannot be undone. |
| Invalid data requires explicit reset | Avoid silently replacing an unreadable practice. | No migration/export of incompatible states; the app intentionally starts over only with confirmation. |
| Temporary mode retains current state | Storage failure should not erase the active practice. | A refresh can lose it; the UI says so. If later saves succeed, persistence resumes. |
| Warm journey beside workspace | Connect a decision to the visible destination and progress. | Two columns become one on narrow screens; the workspace remains available below. |

## Alternatives and scope boundary

Setup-first introduces unrelated prerequisites; a blank workspace serves experienced users who can invent their own trial. An illustrated tour is the simpler fallback if interaction fails to answer the product question. Do not broaden goal coverage solely because this example looks polished.

The software evidence establishes committed behavior only. It cannot establish customer activation, retention, revenue, support savings, fit, or accessibility for every assistive technology. No real customer data, employer materials, external services, or AI generation enters the sample. No claimed human review or commercial result is attached to it.
